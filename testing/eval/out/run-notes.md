## Environment artifacts (discount these)

- **Roster size.** The eval companies inherited the local dev company's roster: 142 rows, most of them harness-created test people ("H10-745589 Dinis", "s1-…" names). A 90-name send list with no search is partly this. The absence of search on that list is still a fair observation for a 20-person company.
- **Tool matching, early on.** Until about 20:00 ET the `click "text"` command did not tolerate curly apostrophes or em dashes ("Let's go", "— File rig checklist"). Complaints about those buttons before then are tool artifacts, not product findings. Fixed since.
- **Screenshots were 2× scale until about 20:10 ET**, and agents' `tap x y` misses before then were coordinate scaling confusion, not the app. Verified after the fix: a tap on a plan hole with the "⌀ No hole" brush selected removes it. Agents who still could not remove a hole after the fix most likely tapped without selecting that brush — the footer text "With an empty brush, tapping erases" is a fair product finding (it erases exceptions, not holes).
- **Accessibility-tree-only interaction.** The agents "see" the accessibility tree. Unlabeled buttons (Rows/Cols −/+, clock icons on the time card) and SVG holes without names are invisible to them where a sighted person would see them. Treat those as accessibility findings (real, and cheap to fix), but do not count them as "a blaster could not find the button".
- **`fill` and React.** One agent believed `fill` set the field but not React state (sign-in needed Enter). Playwright's fill does fire input events; treat this as unverified.
